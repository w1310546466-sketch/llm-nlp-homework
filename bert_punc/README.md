# bert-punc：用 BERT 给中文断句加标点

《大语言模型与应用实践》第二讲那道"高效率的 BERT 古文断句标点"练习的实现。

核心不是把 BERT 微调起来（这一步教程很多），而是**推理的时候怎么不被 512 个 token 卡死**。课件点名的做法是"每次读 400 字、只取前 300 字、退回句号再开始"，慢且浪费；这里改成固定窗口 + 重叠 + 整批前向，同一段文本的前向次数可以少一个数量级。

## 做了什么

- 现代文（人民日报 1998）上去掉标点作为输入，逐字预测 `{O, ，, 。, ？, ！}`
- BERT-base-chinese 微调，单卡 RTX 4060，8 GB 显存
- 评价只看标点位置的 P/R/F1（逐字准确率没有意义，`O` 占九成以上）
- 拿《三国演义》做零样本迁移，看现代文训练的模型能不能给古文断句
- 对比 batch=1/8/32 与课件那种串行做法的真实耗时

## 目录

```
bertpunc/
  decode.py     窗口切分与重叠裁决（纯逻辑，有测试）
  data.py       数据集构造：去标点、逐字标签、子词对齐
train.py        微调与验证

scripts/

data/
  古文样例.txt           4000 字的《三国演义》开头

  train_results.json     训练与验证指标
  guji_results.json      古文迁移与解码对比
```

## 跑起来

```bash
pip install -r requirements.txt

# 1. 准备语料（需要人民日报 1998 原文件）
python scripts/parse_peopledaily.py --src data/raw/*.txt --out data/corpus.txt --max-chars 2000000

# 2. 训练
python train.py --corpus data/corpus.txt --epochs 2 --batch 32 --out results

# 3. 古文评测
python eval_guji.py --model results/model --text data/古文样例.txt
```

模型默认读 `bert-base-chinese`，可以用环境变量 `BERT_MODEL` 指向本地目录。

## 结果

训练：人民日报 1998，40k 句训练 / 4k 句验证，2 轮，batch 32，lr 5e-5，RTX 4060 上 890 秒。

| | Precision | Recall | F1 |
|---|---|---|---|
| 第 1 轮 | 0.9374 | 0.8854 | 0.9107 |
| 第 2 轮 | 0.8957 | 0.9336 | **0.9143** |

零样本迁到《三国演义》（1500 字，窗口 128，与训练一致）：

| | Precision | Recall | F1 | 标点数 |
|---|---|---|---|---|
| 古文 | 0.5291 | 0.4762 | 0.5013 | 210 |

质量掉得很明显，说明模型学到的是现代新闻的标点习惯，而不是通用的句法判断。具体错法看 `results/guji_128_20k.json` 里的 `sample_pred`：它会把"滾滾長江東逝水，浪花淘盡英雄"断成"滾滾長江東逝，水浪花淘盡，英雄"，词界没错，节奏错了。

2 万字长文的解码代价：

| 方案 | forward 次数 | 耗时 |
|---|---|---|
| 窗口 128，batch=1 | 270 | 1.872s |
| 窗口 128，batch=32 | 9 | 0.906s |
| 窗口 510，batch=1 | 39 | 0.721s |
| 窗口 510，batch=32 | 2 | 0.562s |
| 课件串行（400 取 300） | 58 | 0.747s |

批处理把前向次数从 270 压到 9，但端到端只快了一倍左右。原因在报告里写了：课件那种做法每次吃 400 个 token，token 总量并不比我们多，真正吃亏的地方是它没法并行。


## 为什么推理要用批处理

课件里的做法是：

```
读 400 字 → 前向 → 只取前 300 字 → 退回到最近的句号 → 作为下一起点
```

三个问题：下一起点由模型输出决定，所以必须等上一步跑完，batch 永远是 1；每次读 400 取 300，白算 25%；起点总落在句号后，模型永远看不到句中。

只要换成固定长度加重叠，切分就不再依赖模型输出，所有窗口可以一次前向：

```
窗口 1: [0, 128)
窗口 2: [96, 224)     # 重叠 32
```

重叠区按"离窗口边缘最远"裁决，保证每个位置只被采用一次，输出长度严格等于输入长度。

## 测试

```bash
python -m unittest discover -s tests -v
```

窗口切分、重叠裁决、渲染都是纯函数，不需要 GPU 也能测。

## 说明

- 语料是课程分发的人民日报 1998，不随仓库分发；`scripts/` 里的解析脚本按原格式处理。
- 训练脚本里的 `--max-len 128` 是权衡：句子更长时窗口变大，训练更慢，但上下文更足。
- 中文 BERT 基本一字一 token，所以字符位置和 token 位置一一对应；换成会切子词的 tokenizer 时必须改 `data.py` 里的对齐逻辑，否则标签会错位。
