# l4：两次实验

第四讲的两道练习，都在第 130 页与第 135 页，共用同一批课程数据（1656 条参考译文、504 条错例、122 条润色）和同一个本地模型（Qwen2.5-1.5B-Instruct）。

| 文件 | 对应 | 内容 |
|---|---|---|
| [报告.md](报告.md) | 第 130 页 研究练习 | 四种调用协议的对照（直接 / 分解 / 多候选 / 验证选择） |
| [系统.md](系统.md) | 第 135 页 落地练习 | 译文审校助手：基线、加检索、九次二分 |

## 第 130 页的实验

```
prepare.py        抽样生成 data.json（不随仓库提交）
run_protocols.py  四个协议 + 错例检出，需要本地模型
retrieval_only.py 只用 BM25 的检索实验，不需要模型
analyze.py        把轨迹整理成表
results/          summary / traces / retrieval_only
```

| 协议 | 覆盖 | 选择损失 | 平均 F1 | 调用 |
|---|---|---|---|---|
| A 直接调用 | 1.000 | 0.000 | 0.721 | 1 |
| B 单条分解 | 0.833 | 0.000 | 0.682 | 2 |
| C 多候选聚合 | 1.000 | 0.032 | 0.698 | 4 |
| D 验证选择 | 1.000 | 0.044 | 0.711 | 4 |

单次调用最好，分解显著变差（配对 t = −2.09），加候选与加检查项都没超过它。

另有一个前置否定结果：按源句检索历史错例再取"错误原因"做检查项，在获取端就不成立——可归类样本上 top1 类型一致 0.217，原因文本 4-gram Jaccard 0.006。

## 第 135 页的实验

```
system/run_system.py  基线 vs 加检索参照
system/run_binary.py  九次二分判断
system/results/       两条轨迹与汇总
```

| | 格式合规 | 判出问题 | 类型分布 |
|---|---|---|---|
| 基线 | 100% | 24/24 | 漏译 24/24 |
| 加检索 | 100% | 24/24 | 漏译 23 + 一致性 1 |
| 九次二分 | — | — | 每题平均判出 7.3 类（9 类中） |

格式全合规、引用基本真实（21/24 引到原文里的词），但类型判别塌成单一类；拆成二分后反向失败，几乎每类都答"是"。两次失败方向相反，指向同一个结论：瓶颈是模型的判别能力，不是协议。

## 复现

需要 Python 3.10+、torch、transformers，以及本地 Qwen2.5-1.5B-Instruct（约 3 GB）。课程数据放在 `D:\DSH\大语言模型\` 下，路径写在脚本开头。

```bash
python prepare.py && python run_protocols.py && python retrieval_only.py
python system/run_system.py && python system/run_binary.py
```
