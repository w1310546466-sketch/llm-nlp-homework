# l4：四种调用协议的对照

第四讲第 130 页研究练习的实现与结果。报告见 [报告.md](报告.md)。

## 目录

```
prepare.py        从课程数据里抽样，生成 data.json（不随仓库提交）
run_protocols.py  四个协议 A/B/C/D + 错例检出，需要本地模型
retrieval_only.py 只用 BM25 的检索实验，不需要模型
analyze.py        把轨迹整理成表
results/
  summary.json        四个协议的汇总指标
  traces.json         逐条轨迹（120 KB）
  retrieval_only.json 检索覆盖率实验
```

## 复现

```bash
# 1. 抽样（需要课程给的三份 json 放在指定路径）
python prepare.py

# 2. 四种协议，需要 Qwen2.5-1.5B-Instruct 与 8 GB 显存
python run_protocols.py

# 3. 检索实验，不需要模型
python retrieval_only.py

# 4. 出表
python analyze.py
```

## 主要结果

| 协议 | 覆盖 | 选择损失 | 平均 F1 | 调用 |
|---|---|---|---|---|
| A 直接调用 | 1.000 | 0.000 | 0.721 | 1 |
| B 单条分解 | 0.833 | 0.000 | 0.682 | 2 |
| C 多候选聚合 | 1.000 | 0.032 | 0.698 | 4 |
| D 验证选择 | 1.000 | 0.044 | 0.711 | 4 |

单次调用最好，分解显著变差（配对 t = −2.09），加候选与加检查项都没能超过它。

另有一个前置的否定结果：按源句检索历史错例再取“错误原因”做检查项，在获取端就不成立——可归类样本上 top1 类型一致只有 0.217，原因文本 4-gram Jaccard 0.006。所以 D 改用了全局清单。

## 说明

模型是 Qwen2.5-1.5B-Instruct，24 条题，数字只够看方向，不足以支撑细粒度比较。字符 F1 仅用于判断“候选里有没有好的”，不是优化目标。
