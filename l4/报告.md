# 四种调用协议的对照：加计算为什么没有变好

**出处**：第四讲 第 130 页。

**题目**：研究练习——同一应用目标的四种调用协议：最精准翻译的现实需求。

**题面**：先固定正确材料，区分计算的贡献，再单独开放外部信息与反馈。选择标准文档翻译为目标，明确产物和验收条件，划分开发与独立测试任务。明确研究问题，知晓数据来源，明白可用工具以及人力资源，确定研究预算或成本，制定研究路线。比如：先用同一份材料比较直接调用、单条分解、多候选聚合和同候选库上的验证选择，记录覆盖、选择与总成本。再开放一次检索或工具反馈，设置固定正确材料的对照，观察失败来自信息获取还是信息使用。提交汇总结果与完整失败轨迹，提出一项最可能改变判断的最小实验，并说明它需要什么观察。

**课件要求**：先写清实验表再运行——每种协议读什么信息、允许哪些动作、预算如何扣除、失败怎样计分。若一个协议额外得到正确证据，应另设条件解释信息收益。报告用真实运行数据，不把模拟算例填成实验结果。

## 数据

课程给的三份文件是一套完整的材料：

| 文件 | 条数 | 内容 |
|---|---|---|
| `correct_translations.json` | 1656 | 原文 + 参考译文 |
| `translation_errors.json` | 504 | 原文 + 错误翻译 + 错误原因 + 正确翻译 |
| `contextual_polish.json` | 122 | 原文 + 原译文 + 瑕疵说明 + 修订译文 |

一个关键的结构事实：**504 条错例和 122 条润色案例，原文全部能在 1656 条正确译文里找到**。也就是说每条错误都有一个标准答案，可以做“检测—修订”的闭环，不必用 BLEU 打分。

本次实验从中取 24 条译文题（原文 30–80 词）、24 条错例题，检索库用全部 504 条。

## 四个协议

| | 做什么 | 调用次数 |
|---|---|---|
| A 直接调用 | 一次翻译 | 1 |
| B 单条分解 | 先列术语、结构、易错点，再译 | 2 |
| C 多候选聚合 | 3 个候选，模型自选 | 4 |
| D 验证选择 | 3 个候选 + 8 条检查项，逐条核对后选 | 4 |

模型是本地 Qwen2.5-1.5B-Instruct，RTX 4060，33.5 token/s，全程 387 秒。

## 评价口径

不追 BLEU。四个指标：

- **覆盖**：候选集里有没有 F1 ≥ 0.55 的版本（单候选的 A/B 就退化为“这条对不对”）
- **选择损失**：选中的与候选里最好的差多少
- **失败分类**：无可用候选 / 有但选错 / 通过，分别对应生成、选择、修订
- **成本**：调用次数

字符 F1 只作诊断，用来判断“候选里有没有好的”，不是优化目标。

## 结果

| 协议 | 覆盖 | 选择损失 | 平均 F1 | 调用 | 与 A 的配对差 | t |
|---|---|---|---|---|---|---|
| A | 1.000 | 0.000 | 0.721 | 1 | — | — |
| B | 0.833 | 0.000 | 0.682 | 2 | −0.039 | −2.09 |
| C | 1.000 | 0.032 | 0.698 | 4 | −0.023 | −1.40 |
| D | 1.000 | 0.044 | 0.711 | 4 | −0.010 | −1.00 |

配对检验按 24 条逐条对齐。B 的 −2.09 在 5% 边缘，C 和 D 都不显著。

**单次调用最好，其余三个都没超过它。** 这是这次最直接的结果，也是我没预料到的。

## 失败轨迹

按阈值 0.55 分：

```
A: 通过 24 / 选错 0 / 无可用候选 0
B: 通过 21 / 选错 0 / 无可用候选 3
C: 通过 22 / 选错 2 / 无可用候选 0
D: 通过 24 / 选错 0 / 无可用候选 0
```

三条线索：

**B 的三个失败是“无可用候选”**，分解那一步引入了错误。看轨迹能看出原因：模型的“术语与结构分析”经常复述原文内容，把“易错点”写成了内容摘要，第二步拿着这份摘要翻译，等于多了一次被误导的机会。

**C 的两个失败是“有正确候选但选错”**。这是纯粹的选错问题——候选中存在更好的版本，模型挑错了。比如某条三个候选的 F1 是 0.83 / 0.71 / 0.61，模型选了 0.61 那条。

**D 没有失败，但增益也在噪声内**。D 和 C 在 7/24 条上选不同，互有胜负：有的条 D 选对了 C 选错（0.546 → 0.676），有的反过来（0.710 → 0.613）。八条检查项并没有稳定地把选择变好。

## 一个前置的否定结果：错误记忆检索不成立

D 最初的设计不是全局清单，而是**按源句检索历史错例，用邻居的“错误原因”当检查项**。落地之前先量了一下获取端：

对 504 条错例逐条离群检索，看最近 3 条历史错例的错误原因能否覆盖这条：

```
能按关键词归类的 212 条（42%）
仅看可归类的：top1 类型一致 0.217，top3 至少一条一致 0.401
错误原因文本 4-gram Jaccard：0.006
```

随机基线约 0.11，0.217 只是略高于随机；Jaccard 0.006 说明检索到的邻居和目标**几乎没有共同措辞**。

原因不难理解：BM25 按英文源句检索，找到的是话题相近的句子，而错误是局部的——“has been granted authorization 被译成资质认证”和“latter 指代不清”都在讲标准文档，但错在不同位置。话题相近不等于错误同源。

所以按条检索的方案在**获取端**就断了，还没到“用不用得上”的问题。这直接导致 D 改成全局清单：不赌检索精度，先保证清单本身相关。

这一段是本实验里我自己认为最有价值的部分——它把“信息获取”和“信息使用”分开了，而且结论是前者不成立，不是后者。

## 错例检出实验

给 24 条错例的原文和错误翻译，问模型“这段译文有什么问题”。

自动判分（要求与参考原因逐字重合）只有 4.2%，但那个指标是坏的——参考原因写得很具体（“3.3.24 已有资格条件的定义没有形成应有区别”），模型不会用同样的措辞。

人工逐条判读后，真正指出问题所在的约 4–6 条，17%–25%。典型命中：

- 目标“75% 的分母是参与投票成员，坏译扩大为全体成员”，模型给出了带限定语的改写
- 目标“general 是一般性/适用范围”，模型指出“通常”一词不准确

典型未命中：

- 目标“主语是框架集，谓语是 groups”，模型回答“目标是对句法描述进行分解复用”——完全跑偏
- 目标“intuitive 不是主观”，模型回答“本段翻译没有问题”

1.5B 在“定位具体错误”这件事上很弱：它倾向于给出通顺但不相关的评论，或者干脆说没问题。这解释了 D 为什么没赢——检查项是对的，但执行检查的模型看不住。

## 一个最小实验

如果只能再做一个实验，我会做**选择器的对照**：固定 C 和 D 生成的候选集，只换选择环节——分别用规则（最长/最短）、模型自评、外部更大的模型来选，看选择损失能不能从 0.03 降下去。

需要什么观察：同一批候选上，三种选择器的选中 F1 差异。如果差异大，说明瓶颈在选择，值得投入；如果都差不多，说明候选之间的差别本来就是噪声，加计算确实没用。

这个实验不需要重新生成，成本只有选择环节的调用，是当前信息量最高的一步。

## 局限

只有 24 条题，配对差在 0.01–0.04 的量级，和噪声同阶，C 与 D 的差别不能当结论。模型是 1.5B，不代表更大模型的表现——但“加计算没帮助”这个方向性结果，在小模型上出现并不奇怪：它的分解和自评能力都不足以支撑多步协议。

字符 F1 和参考译文比，对同义改写的惩罚偏重，这也是不把它当目标的原因。
