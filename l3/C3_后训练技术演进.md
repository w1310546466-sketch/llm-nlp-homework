# 后训练这几年在变什么

**出处**：第三讲 part2 第 226 页。

**题目**：思考题——大语言模型后训练技术的演进（课件标注"考虑必做"）。

**题面**：

1. 后训练的目标发生了怎样的变化？
2. 后训练算法如何演进？
3. 训练数据与奖励机制如何发展？
4. 新一代模型的训练流程有哪些值得关注的创新？
5. 论文方法如何转化为实际训练程序？

**课件要求**：入门写一篇 2023–2026 后训练路径与方法的对比综述，不要单篇论文摘要的集合；有基础的深入 2–3 个开源后训练代码。交付 4–6 页报告、一张演进图、一张比较表、一份代码分析说明。评分：技术理解与比较 40%，算法与代码对应 30%，实验或工程分析 20%，独立思考与表达 10%。

## 一、先说我读的几份东西

InstructGPT、DeepSeek-V3、R1、Qwen3、V3.2，这五份是从头看到尾的。DPO 原文是补读的，因为不读它没法解释 2023 年那一波"不要奖励模型"的风潮。

课件还列了 Kimi K2.5 和 GLM5。GLM-5 我只在 Hugging Face 上看到仓库，技术报告的方法部分没找到公开版本；Kimi K2.5 连一手材料都没搜到。所以我下面讲的东西全部来自前五份，这两家不参与论证。如果它们确实发了方法细节，那我少的那块大概是多模态和智能体结合的部分。

## 二、目标其实换了三次

2022 年 InstructGPT 要的是"有用、诚实、无害"。做法是三步：人写示范做 SFT，人给两个回答排序训奖励模型，然后 PPO 把奖励做大。这套东西的前提很朴素——质量由人判断。

R1 要的是"这题能不能做对"。看似只是任务换了，实际变化在判定上：数学题有标准答案，代码能跑测试，对错的判定不需要人了。这一步一跨过去，训练数据的成本掉了一个量级，RL 才有可能大规模跑。

V3.2 再往前一步，要的是"能不能在多轮工具调用里把事情办成"。这时候判定信号来自环境——工具返回什么、代码有没有跑通——比"答案对不对"更稀、更慢。

判定权从人手里挪到程序手里，再挪到环境手里，这是我认为这三年最实质的变化。算法本身反而没那么多新东西。

## 三、算法：每一代都在砍一个组件

SFT 最省事，只要示范。但它没有负样本，模型只学会"写得像人"，学不会"哪种写法更好"。

PPO 把这件事补上了，代价是显存里同时躺着四个模型：策略、参考、奖励、价值。目标函数里三项各司其职，奖励管方向，KL 管别跑偏，价值网络管降方差。我第一次搭 PPO 的时候被价值网络的形状搞了很久，它和策略同规模，等于凭空多一个模型。

DPO 是 2023 年那篇，它证明在 Bradley–Terry 偏好模型加 KL 约束下，最优策略有闭式解，于是"训奖励模型 + PPO"能合并成一个分类损失：

```
− log σ( β · [ (log π(y_w) − log π_ref(y_w)) − (log π(y_l) − log π_ref(y_l)) ] )
```

奖励模型没了，在线采样没了，价值网络没了。剩下的东西很少，这也是它流行的原因——一个人一台机器就能跑。

但这里有个我当时没想明白的地方。DPO 优化的是"相对参考模型的偏好增益"，不是绝对质量。也就是说，如果参考模型本身很差，DPO 也能把"稍微没那么差"的回答推上去，看起来训练很顺，实际能力没涨。后来看到一些"DPO 提升的是偏好匹配而不是解题能力"的实验，才对上。

GRPO 砍的是价值网络。同一道题采样 G 个答案，组内奖励的均值和标准差本身就是基线，不需要再学一个网络去估：

```
A_i = (r_i − mean(r)) / std(r)
```

我原以为这一步的意义是省显存，看代码之后发现有更要紧的地方——**标准差那一步不能省**。如果一组奖励全一样（全对或者全错），分子分母同时趋零，梯度就没了。所以实现里必须加个 `1e-4` 兜底，还得用 `nanmean` 处理异常值。这些论文不会写。

RLVR 再往前砍，连奖励模型都不要了，直接用规则判分。到这一步，整条链路里除了策略和参考模型，其余全是程序。

砍到头会撞墙：能自动判分的任务只覆盖"有标准答案"的那部分。写作、翻译、开放问答这些还是得回到人或者模型来评。

## 四、数据：造比标便宜

按监督信号怎么来的分，有四代。

人写示范最贵。人给偏好便宜一些，但标注者之间一致性常常不高，同一对回答换个标注员结论就反了。第三代是模型自己生成多条，用规则或奖励筛出对的，再拿去 SFT——R1 的第三阶段就是这么干的。这一步的意义不只是"造数据"，它是把 RL 学到的能力固化回模型，免得推理时每次都拉长链。

第四代是环境反馈，工具返回值、测试结果。最真实，也最稀疏。

奖励的粒度也在变细：只看最终答案，到给每一步打分，到给整条轨迹打分。细的密，但过程奖励本身要靠模型或人工来给，模型自己判错的地方会变成训练目标——这是个循环。

## 五、三家怎么排流程

R1 是五段：先 R1-Zero，纯 RL，只给规则奖励，不做 SFT 冷启动。跑出来发现可读性差、中英混杂，于是加冷启动 SFT，再做推理 RL，然后用拒绝采样生成 SFT 数据，最后做一轮全场景 RL（把写作、问答也塞进去，防止只会做题）。

R1-Zero 那个结果比 R1 本身更有意思：不给任何人类示范，只靠"答案对不对"这一个信号，模型自己长出了推理链。这在 2024 年是不太敢想的。

Qwen3 也是四段，但重点不一样：长 CoT 冷启动、推理 RL、思考模式融合、通用 RL。第三步是关键，它把"想"和"不想"两种模式蒸进同一个模型，用 chat template 切，而不是养两个模型。这解决的是部署问题——没人愿意为一个"今天天气怎么样"付三千 token 的延迟。

V3.2 三项突破里只有两项是后训练：可扩展的 RL 框架（把 RL 算力堆上去，效果对标 GPT-5 那一档）和智能体任务合成（自动造工具调用任务）。第三项 DSA 是注意力结构，和后训练没关系。

三家有个共同点，都在做合成任务。真实任务标不起的时候，造任务比标任务便宜。V3.2 明说它智能体能力来自合成的交互环境。

## 六、从公式到代码

我在本地浅克隆了 TRL，跟着论文公式找了一遍实现。行号是克隆那一刻的，过几天可能会变。

DPO 在 `trl/trainer/dpo_trainer.py`。`_compute_loss` 在 1362 行，先算 chosen 和 rejected 的序列对数概率，各自减去参考模型的，第 1460 行把两者相减得到 `delta_score`，第 1465 行 `-F.logsigmoid(self.beta * delta_score)`，和论文公式一字不差。

论文没提的是 `loss_type` 还能取 `hinge`、`ipo`、`bco_pair`，`f_divergence_type` 能换 KL 的方向，甚至连 alpha 散度都有（1441 行）。也就是说论文那个 sigmoid 只是这一族里的一个点，换一下就是另一篇论文。

GRPO 在 `grpo_trainer.py`。生成和打分在 2458 行的 `_generate_and_score_completions`，每个 prompt 采 G 条（`num_generations`，838 行）。组内标准化在 2913 到 2935 行，就是上面那个公式，加 `1e-4`、用 `nanstd`。损失在 3089 行的 `compute_loss`，逐 token 拿 advantage 加权（3206 行），第 3304 行加上 `beta * per_token_kl`。

代码里还有一堆论文没有的东西：`off_policy_mask` 处理 vLLM 采样和训练策略不一致（3219 行），`entropy_mask` 只在高熵 token 上算梯度（3200 行），`vllm_importance_sampling_correction` 做重要性采样修正（3300 行）。这些才是让它真能跑起来的部分。论文告诉你为什么，代码告诉你怎么活。

## 七、演进图

```
2022  InstructGPT   SFT → RM → PPO                    （人判，四个模型）
2023  DPO           SFT → DPO 损失                     （去掉 RM 和在线采样）
2024  GRPO          SFT → 组内基线 + 规则奖励           （去掉价值网络）
2025  R1            R1-Zero → 冷启动 → 推理 RL → 拒绝采样 → 全场景 RL
2025  Qwen3         长 CoT 冷启动 → 推理 RL → 思考融合 → 通用 RL
2026  V3.2          可扩展 RL + 合成智能体任务          （判定交给环境）
```

三条线同时在走：砍昂贵组件（RM、价值网络、在线采样）、换判定信号（人、模型、程序、环境）、换数据来源（示范、偏好、拒绝采样、任务生成）。

## 八、比较表

| | 数据 | 奖励模型 | 价值模型 | 参考模型 | 在线采样 | 解决什么 | 又带来什么 |
|---|---|---|---|---|---|---|---|
| SFT | 示范 | 否 | 否 | 否 | 否 | 冷启动、格式 | 没有负样本 |
| PPO | 偏好 + 在线 | 是 | 是 | 是 | 是 | 优化不可微目标 | 四模型同显存，不稳 |
| DPO | 偏好对 | 否 | 否 | 是 | 否 | 去掉 RM 和在线循环 | 吃离线分布，偏好不等于能力 |
| GRPO | 可验证任务 | 否 | 否 | 是 | 是 | 去掉价值网络的 RL | 要求组内有方差，全对全错没梯度 |
| RLVR | 规则、测试、环境 | 否 | 否 | 看实现 | 是 | 大规模自动 RL | 只覆盖可判定任务，容易奖励黑客 |

## 九、几个我还没想清楚的

第一个是"判定成本"这个说法能不能撑住。我把三年的变化归结为判定权转移，但这解释不了为什么 SFT 今天还在用——SFT 的判定成本是零（根本不用判定），它没被替代，只是变成了起点。所以更准确的说法可能是：判定成本的下降决定了**能用 RL 的范围**，不是决定用什么方法。

第二个是合成数据的边界。R1 的拒绝采样、V3.2 的任务生成，本质都是"生成 + 筛选"。筛选器错了，错误会被固化进模型，而且比人工标注错得更系统。这条线的风险我看到的材料里讨论得都不多。

第三个是多模态和智能体。课件点了 Kimi K2.5 和 GLM5，我没拿到材料，这一块空着。如果它们真在做"并行智能体 RL"，那可能是我这三条线之外的第四条：**把单条轨迹的 RL 扩展到多条并行轨迹**。我没有证据，只是猜。
